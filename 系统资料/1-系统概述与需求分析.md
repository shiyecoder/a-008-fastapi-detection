# 基于FastAPI+Vue的Webshell检测平台的设计与实现 - 系统概述与需求分析

## 一、系统概述

### 1.1 研究背景

随着信息服务信息化建设的推进，业务单位对业务办理的规范性、数据留痕的完整性以及查询统计的实时性提出了更高要求。在Webshell检测平台这类场景中，业务通常横跨线路、公共等多个环节，参与者既有目标用户，也有后台管理人员。

这些环节如果依靠纸质台账、分散的 Excel 表格或即时通讯工具来维持，常见的问题有三类：一是同一份数据在不同环节重复录入，口径不一致；二是状态变更（如提交、审核、完成）缺少统一记录，事后追责困难；三是数据分散在各人手中，无法形成可用的统计视图。把上述流程收敛到一套信息系统内，让数据只录入一次、状态由系统推动、统计由数据库直接汇总，是这类课题的主要出发点。

与单纯的台账管理不同，本课题还带有明显的数据分析诉求：系统需要把业务过程中沉淀下来的原始记录转化为可读的指标与图表，帮助业务单位从数据中发现规律。因此系统在设计上同时包含“业务数据采集”与“指标计算 / 可视化呈现”两条主线。

### 1.2 系统目标

本系统以 **FastAPI + Vue 3.x + MySQL 8.0** 为技术栈，目标是构建一套“角色清晰、流程完整、数据可查”的Webshell检测平台，具体目标包括：
- 为管理员提供线路、公共等后台管理能力，保证基础数据可维护、业务记录可追溯；
- 为普通用户提供线路、公共等前台功能，覆盖从进入到办结的完整链路；
- 以 15 张数据表承载业务实体，保证sys_user、sys_role、sys_menu、sys_user_role之间的关联关系在数据库层面有明确约束；
- 对外提供 72 个接口，前后端通过统一的响应结构（JSON）交互，降低联调成本；
- 功能范围覆盖：四引擎并行检测、多语言规则库、规则热更新、告警生成与分级、风险文件隔离还原、检测报告导出；
- 在部署上只依赖 Python 运行环境与 MySQL，不引入 Redis、消息队列等中间件，保证在单机上可完整运行。

### 1.3 系统特点

1. **单端集中**：Vue 管理后台，所有功能在同一入口内完成，交互路径短。
2. **角色划分**：`admin` / `user`，权限通过用户表的角色字段控制。
3. **数据规模**：15 张业务表、72 个接口、2 个功能模块，表与表之间通过主外键与业务字段关联。
4. **技术要点**：ECharts 图表。
5. **轻依赖部署**：仅需运行环境 + MySQL，导入 SQL 即可启动，无第三方服务依赖。

## 二、需求分析

### 2.1 用户角色分析

| 角色 | 标识 | 角色值 | 角色说明 | 主要功能 |
|------|------|------|------|------|
| 管理员 | `admin` | 1 | 后台数据与用户管理 | 后台全部管理功能 |
| 普通用户 | `user` | 2 | 前台业务办理 | 业务办理与数据查看 |

角色在数据库中的落点：用户表 `sys_user`。

### 2.2 功能需求

#### 2.2.1 公共与统计功能

| 功能模块 | 功能点 | 功能描述 |
|------|------|------|
| 公共功能 | 业务处理、列表查询、删除、登录、注册、获取当前用户信息 | 对应接口 72 个，如 `GET /` |

### 2.3 非功能需求

| 需求类型 | 需求描述 |
|------|------|
| 性能需求 | 页面首屏加载时间控制在 3s 以内。 |
| 安全需求 | 密码使用不可逆算法存储；接口通过 Token / Session 校验登录态；上传文件限制类型与大小。 |
| 可用性需求 | 界面遵循主流组件库交互规范，常用操作 3 次点击内可达；表单必填项有前置校验与提示。 |
| 可扩展性需求 | 后端按 Controller / Service / Mapper 分层，新增业务只需扩展一组文件；数据表字段预留状态位，便于后续增加流程节点。 |
| 数据一致性 | 关键写入操作在服务层集中处理，避免前端直接拼 SQL。 |
| 兼容性需求 | 管理端兼容 Chrome 90+ / Edge 90+；页面在 1366×768 及以上分辨率正常显示。 |

## 四、业务流程分析

### 4.1 登录鉴权流程

```
用户打开登录页
          ↓
POST /auth/login
          ↓
服务端校验账号是否存在 → 校验密码 → 校验状态
          ↓
     ┌────┴────┐
   通过        失败
     ↓           ↓
签发 Token    返回错误提示
     ↓
前端写入本地存储，跳转首页
```

### 4.2 线路模块主链路

```
线路模块主链路

1. GET /alert/page  →  列表查询
2. PUT /alert/handle/{aid}  →  业务处理
3. DELETE /alert/delete/{aid}  →  删除
4. POST /auth/login  →  登录
5. POST /auth/register  →  注册
6. GET /auth/info  →  获取当前用户信息
```
