本章按业务模块说明实现过程。系统共划分为 **2 个模块**、**72 个接口**，下面按调用频次与业务重要性依次展开。

|------|------|------|------|------|

## 一、线路模块

### 1.1 功能概述

线路模块对内对外共提供 **71 个接口**，覆盖列表查询、业务处理、删除、登录、注册、获取当前用户信息、退出登录、统计汇总等动作，数据主要落在 相关业务表。

后端由 `router` 承载，对应前端页面 1 个。

接口清单：

| 方法 | 路径 | 处理方法 | 动作 |
|------|------|------|------|
| `GET` | `/alert/page` | `list_alerts` | 列表查询 |
| `PUT` | `/alert/handle/{aid}` | `handle` | 业务处理 |
| `DELETE` | `/alert/delete/{aid}` | `delete_alert` | 删除 |
| `POST` | `/auth/login` | `login` | 登录 |
| `POST` | `/auth/register` | `register` | 注册 |
| `GET` | `/auth/info` | `get_info` | 获取当前用户信息 |
| `POST` | `/auth/logout` | `logout` | 退出登录 |
| `GET` | `/dashboard/overview` | `overview` | 统计汇总 |
| `GET` | `/dashboard/trend` | `trend` | 统计汇总 |
| `GET` | `/dashboard/lang-distribution` | `lang_distribution` | 业务处理 |

### 1.2 关键流程

```
用户进入「线路」页面
          ↓
前端携带分页与筛选条件请求列表接口
          ↓
GET /alert/page
          ↓
服务端按条件拼接查询 → 分页 → 返回列表
          ↓
表格渲染，用户选择一条记录继续操作

──▶ 删除分支：DELETE /alert/delete/{aid}
         ↓
二次确认 → 按主键删除（或置删除标记）
```

**`generate`** —— 业务处理，对应接口 `POST /report/generate`

def generate(body: ReportIn, db: Session = Depends(get_db):
"""生成报告"""
content = {"sections": []}
risk = "safe"

if body.report_type == "comprehensive":
    # 综合：取最近若干任务汇总
    det = db.query(DetectionTask).order_by(DetectionTask.id.desc()).limit(20).all()
    content["sections"].append({
        "title": "Webshell检测概览",
        "items": [{"id": t.id, "name": t.task_name, "risk": t.risk_level, "hits": t.hit_count} for t in det]
    })
    risks = [x.risk_level for x in det if x.risk_level]
    risk = "high" if "high" in risks else "medium" if "medium" in risks else "low"
elif body.report_type in ("static", "dynamic") and body.related_task_id:
    t = db.query(DetectionTask).get(body.related_task_id)
    if not t:
        return fail("任务不存在")

接口清单：

| 方法 | 路径 | 处理方法 | 动作 |
|------|------|------|------|
| `GET` | `/` | `root` | 业务处理 |

### 2.2 关键流程

```
用户发起操作
          ↓
GET /
          ↓
服务端校验参数 → 执行业务 → 返回结果
```

### 2.3 实现说明

该模块的接口由框架路由直接映射到处理函数，核心逻辑集中在服务端对数据表的读写与参数校验上；请求参数与返回结构遵循第 2 章 3.4 节的统一约定。
